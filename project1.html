    Tool calling & execution
    
      
    Who picked the filename?
    
      
    Keep the model and Python script fixed. Change the tool Pi offers, and you change the decision Kimi gets to make.
    
      
    
        
    InterfaceKimi suppliesWhat happens on your VM
    
        
          
    bash{"command":"python3 timing.py A"}Pi passes that command to a shell. Kimi chose the program, filename and ID.
    
          
    get_timing{"request_id":"A"}Your registered handler starts python3 directly. The handler fixes the filename and passes the chosen ID as a separate argument.
    
            
      
    
      
    Read the exact extension from this lab
        
    registerTool runs when Pi loads the TypeScript file. execute runs later when Pi receives a valid call. TypeScript defines the interface; Python implements the lookup.
    
        
    import { Type } from "typebox";
import { StringEnum } from "@earendil-works/pi-ai";
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function (pi: ExtensionAPI) {
  pi.registerTool({
    name: "get_timing",
    label: "Get timing",
    description: "Look up a synthetic timing record for request A or B.",
    parameters: Type.Object({ request_id: StringEnum(["A", "B"] as const) }),

    async execute(_callId, { request_id }, signal) {
      // The model chooses the ID. We choose the program and file.
      const result = await pi.exec("python3", ["timing.py", request_id], { signal });
      if (result.code !== 0) throw new Error(result.stderr.trim() || "Timing lookup failed");

      // Pi includes this text in the next model request.
      return { content: [{ type: "text", text: result.stdout.trim() }], details: {} };
    },
  });
}
    
        
    stdout holds the printed record. A nonzero exit makes the handler throw with the error from stderr. signal carries cancellation. The returned content becomes evidence Kimi can use in its reply.
    At the Ubuntu prompt, typing python3 timing.py A runs Python directly. The separate starter extension also offers a Pi slash command, /timing A, which runs local code. In the VM session reconstructed here, you asked a question in plain English and Kimi chose the registered tool.
    
      
    
    
    
    
    
      
    Guardrails
    
      
    Where did G stop?
    
      
    Observed. Kimi read the A/B rule and replied directly. There was no tool-call box. Pi never received an argument to validate, and Python never ran.
    
      
    If Kimi submitted G. Pi would check it against the enum before running the handler. That would test a different layer.
    
      
    Why did the earlier Bash run exit with code 2?
    That run used python3 timing3.py G. Python started and could not open the misspelled filename. The script never got far enough to check the ID. Reporting the error and asking to list files was a follow-up the model chose.
    
    
    
    
    
      
    Tool design
    
      
    Could two lookups take one call?
    
      
    Today, get_timing takes one ID. A batch tool could accept {"request_ids":["A","B"]} and return a labeled record for each ID. Its handler decides how many times Python starts.
    
      
    Would batching save tokens?
    Two tool requests may arrive in one model response, or B may be requested after A returns. Batching can reduce repeated formatting; in the sequential case it can also remove a model round trip. Both records still enter context. Compare model request counts and total input/output tokens in fresh sessions. We did not measure this saving.

    Quick Revision Flashcards
    Predict each answer, then open the card to check it.
    
  
    
    
    Who knows the filename before Kimi requests A?
    Your extension fixes timing.py in pi.exec. The model-facing schema offers an ID. Kimi can request A without knowing the filename.
    
    
    You add G only in Python. What IDs does Kimi see?
    A and B. Pi reads the allowed IDs from the extension. To expose G, update the schema and description, then reload the changed extension.
    
    
    What would prove Pi rejected an invalid ID?
    A trace showing an attempted call with the invalid argument and a validation error before the handler ran. Kimi’s text-only G reply establishes that it chose to stop earlier.
    
    
    Why can’t 900 ms tell you what to optimize?
    A and B both total 900 ms, but their longest stages differ. You need a stage breakdown for the real workload to justify a change.
    
    
    Two tool calls appeared. How many model round trips happened?
    The tool-call count is insufficient. Inspect the sequence of model requests and responses to see whether Kimi chose both calls together or waited for the first result.
    
    
    Did Kimi learn a new skill when you registered the tool?
    You changed the actions Pi described and allowed. The same model could now request a timing record using one argument. The experiment involved no model training.
